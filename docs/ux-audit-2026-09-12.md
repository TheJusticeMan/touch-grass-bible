# Touch Grass Bible UX audit

Audit date: 2026-09-12  
Scope: local web app at `http://127.0.0.1:3000/`, desktop-width browser session.

## Method

I opened the initial reader and the command palette, then opened every visible top-level command category and its immediately presented submenu/state. I captured a screenshot at the initial reader, each of the 14 command-category states, and the tested search, translation, and verse-tagging states. I also exercised reader selection, verse actions, Bible search, translation switching, and tagging/bookmarking.

## Site map and feature inventory

### Primary workspace

- **Panel workspace:** independently tabbed Journal, Bible reader, and Knowledge Base panes. The current session presented all three at once.
- **Bible reader:** continuous chapter reading; click a verse to select it; click a chapter heading to open **Go to verse**; right-click a verse to open its TSK cross references.
- **Verse action strip:** Share Verse; Tag verse; OpenBible verse topics; TSK+ cross references; Add Journal Verse Entry; Ask AI about this verse; Nave's topical Bible.
- **Journal:** add a text entry, add an image, or add the currently selected verse.
- **Knowledge Base:** topic tree and Q&A-style topic content, with add controls.
- **Gesture button:** a floating, icon-only button that opens the command palette. This is effectively the application's main navigation.

### Command-palette navigation

The palette's visible top-level categories were:

1. **Topic** - manages the selected verse's topic/tag relationship; supplies Edit Topic and Back to Your Topics actions.
2. **Cross references for [selected verse]** - opens a scrollable list of linked passages.
3. **Your Topics** - personal topic/Q&A collection.
4. **Go to verse** - book/chapter/verse navigator; the empty submenu starts with all Bible books.
5. **Topics (www.openbible.info)** - OpenBible topical lookup.
6. **Search bible** - full-text verse search.
7. **AI Semantic Verse Search** - embedding search; reports that an embeddings JSON file is required.
8. **Translations** - King James Version (KJV), American Standard Version (ASV), and Young's Literal Translation (YLT).
9. **Settings** - includes debug-console and download/data-management settings.
10. **AI Bible Assistant** - theology/verse Q&A; reports that no API key is configured and directs the user to Settings.
11. **Plugin Options** - enable, disable, and configure installed features (including TSK+).
12. **Appearance** - font-size controls and visual customization.
13. **Reading Plans** - daily plan and today's reading (Matthew 1 in this session).
14. **Nave's Topical Bible** - topics, subtopics, and associated passages.

## Core interaction results

| Interaction        | Result                                                                                                                                                             |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Reading pane       | Works: selecting Genesis 1:1 exposed the seven contextual verse actions; the continuous reader contained adjacent chapters.                                        |
| Bible search       | Works: entering `beginning` returned Genesis 1:1, Genesis 10:10, Genesis 13:3, and other text matches.                                                             |
| Translation switch | Works: choosing **American Standard Version** changed the reader content and the tab label from `Genesis 1:1 - KJV` to `Genesis 1:1 - ASV`.                        |

## Confusing navigation patterns and dead ends

1. **The primary navigation is undiscoverable.** The floating arrow/gesture icon has no visible label, tooltip, shortcut hint, or menu affordance. A new user can read, but has little reason to infer that it opens virtually all functionality.
2. **The command palette blurs hierarchy.** The Navigator's category list remains visible while a selected category's content is appended below it. In dense states (especially Cross References), the current context is easy to lose and the palette reads like one long result list rather than a drill-down menu.
3. **Inconsistent vocabulary and duplicated concepts.** "Topic," "Your Topics," "Tag verse," "Knowledge Base," "Topics (www.openbible.info)," and "Nave's Topical Bible" overlap semantically. In particular, the user-facing bookmark behavior is called **Tag verse** and displays an unlabeled topic name, so its persistence and purpose are unclear.
4. **Several advertised capabilities start as blocked states.** AI Semantic Verse Search needs generated data; AI Bible Assistant needs an API key. These are valid prerequisites, but the entries initially look usable and lead to configuration/error-style instructions rather than an onboarding flow.
5. **Some labels are implementation-facing.** "Ai Embedding Search," "Plugin Options," and "Debug console" sit alongside everyday reading tools without progressive disclosure. This adds cognitive load for readers who only want scripture navigation.

## Three usability recommendations

1. **Make global navigation explicit.** Replace or accompany the floating gesture icon with a labeled `Browse` / `Command menu` button, a tooltip, and a first-run hint such as "Browse Bible, search, translations, and tools." Add a visible keyboard shortcut.
2. **Turn the palette into a clear two-level flow.** When a category opens, replace the navigator list with that category's items, show a prominent breadcrumb (for example, `Menu / Translations`), and retain one clear Back control. Group advanced tools under an "Explore & settings" section.
3. **Unify verse saving around a familiar model.** Rename **Tag verse** to `Save to topic` (or provide a Bookmark label), show saved-state confirmation and the destination topic, and give the user a one-click `New topic` option. Consolidate personal topics/Knowledge Base terminology and distinguish it from external topical indexes.
